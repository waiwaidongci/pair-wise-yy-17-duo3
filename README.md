# 钟乳石洞穴微环境巡测

围绕洞穴、分区、样点和巡测路线记录微环境数据，并把洞内外排期接成**可恢复批次**。

## 启动

```bash
npm install
npm start          # http://localhost:3912
npm run selftest   # 排期规则自检（独立临时库，不污染 data/db.json）
```

数据保存在 `data/db.json`；原子写（临时文件 + rename），可用 `SCHEDULE_DB=/path/x.json` 指定其他库文件。

## 排期规则（全部由服务端裁决）

- **每日两份设备入洞**：按日期统计 `洞内` 占用，配额 `caveKitQuotaPerDay = 2`；`洞外` 不计入。同队员、同设备、同样点在「日期 + 时段」上唯一，后到者逐条给出冲突原因。
- **先到先占**：所有写请求经 FIFO 写锁串行化并分配到达序号；两人同时提交同一时段，先到者占用，后到者整批保留为**草稿**，可改时段后恢复。
- **可恢复批次**：批次号 `batchNo` 由客户端生成（幂等键）。写入失败后用同一批次号原样/改后重试，不会产生重复批次或重复排期。
  - `POST /api/schedule/batches` `{ batchNo, note, entries: [{ siteId, surveyor, date, slot, location, equipmentId }] }`
  - 重试同一 `batchNo`：只重新仲裁仍是草稿的条目；条目带 `id` 可逐条调整，不带 `id` 按顺序覆盖草稿行。
- **CO2 校准值 / 保护等级一变，立即失效重算**：
  - 尚未开始、进行中、已停测的排期刷新重算依据（控制线上限 = 基准CO2 + CO2校准值）；
  - 样点改为「暂停开放」时，未开始排期立即**停测并释放占用**；恢复开放时重新走占用仲裁，冲突退回草稿；
  - **已完成记录保留现场快照**（完成时的等级、校准值、控制线冻结），后续变更只追加「变更留痕」，不改写快照。
- **状态一致**：占用状态由服务端统一派生到 `/api/db` 的 `occupancy`（配额、日期/时段看板格、样点状态、巡测状态、批次状态），样点卡片、巡测卡片、趋势看板读同一份结果。

排期生命周期：`未开始（已占用）→ 进行中 → 已完成`；冲突时为 `未开始 + 草稿`；样点暂停开放时为 `停测`。草稿未占用时段，服务端拒绝「开始巡测」。直接在「巡测记录」页登记的记录视为现场已完成，创建即冻结快照。
